# 否定结果：给候选打相关性分数解决不了这个问题

起因：BM25 分数在真实用户提问上没有区分度——命中时 top-6 是 `0.07/0.06/0.06/0.06/0.06/0.06`，
未命中时是 `0.06/0.06/0.05/0.05/0.05/0.05`。于是让模型给每个候选打 0-100 的相关性分，
期望用一个"有用的评分"取代坏评分（用于筛减、排序、决定是否加深召回）。

实测（2,996 部法规，12 条自然语言查询，候选池 top-12）：

| 观察 | 数量 |
| --- | --- |
| 正解**不在**候选池（召回失败） | 4 / 12 |
| 正解在池内，评分能正确分开噪声 | 3 / 8 |
| 正解与噪声同分（分离 = 0） | 4 / 8 |
| 正解得分**低于**噪声 | 1 |

噪声候选的最高分达到 **100**，与正解无异。

结论：**问题不在评分，在召回。** 候选池里根本没有正确答案时，再准确的评分也无从判断；
而即使正解在池内，仅凭标题 + 一段摘录，模型也无法可靠判断"这条规定是否在这个文档里"。

改进评分输入的尝试（用与查询字面重合最多的段落替代文档开头）把可分离比例从 0/1 提高到 3/8，
但远不足以支撑排序决策。**不再把评分当作排序/筛减的主手段**。

真正的瓶颈已在前一份 README 中量化：`hit@12 = 0.37~0.49`，即一半以上的真实提问，
正确文档压根没被召回。下一步应当解决召回（查询扩展、文档侧问题合成、更深候选池），
而不是优化对已召回候选的打分。
