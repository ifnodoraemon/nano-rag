# 让阅读计划的判断成为排序，而不只是读取清单

## 机会是怎么发现的

`hit@1 = 0.5259` 已停滞多轮。拆解分布：

```
rank 1:   142
rank 2-4:  67   ← 全部 hit@1 的提升空间
rank 5-12: 33
未召回:    28
```

`hit@4 - hit@1 = 0.248`，即 67 条查询的答案就排在**第 2-4 位**。

看这 67 条的前几名：

| 查询 | 第 1 名 | 正解 |
| --- | --- | --- |
| 现在一对夫妻最多能生几个孩子 | 云南省镇沅县自治条例 | 浙江省人口与计划生育条例（第 2） |
| 饭店、酒楼还能收野味卖吗 | 广西水生野生动物保护管理规定 | 吉林省禁止猎捕陆生野生动物的决定（第 2） |
| 单位不签劳动合同，工会能找谁管 | 武汉市工会条例 | 广西实施《工会法》办法（第 3） |
| 男的多少岁能结婚 | 海南藏族自治州变通规定 | 循化县补充规定（第 3） |

**都是同一主题、同一体裁的法规在竞争**（"XX市工会条例" vs "XX省实施工会法办法"）。
BM25 靠词频无法区分——它们的词汇高度重合。统计这些案例的第 1 名：
市级 33、省级 19、全国性 6、自治区 4。

## 一个已经存在但没被使用的信号

阅读计划（`_plan_reads`）本来就在读每个候选的摘要，回答"哪几篇能回答问题"——**而且是有序的**。

大样本实测（n=435，旧全量 trace 的 `reading_plan.selected_docs` 与实际 `expected_doc_ids` 对照）：

| 排序依据 | hit@1 |
| --- | --- |
| BM25 排第一 | **45.1%** |
| 阅读计划选的第一篇 | **70.3%** |

新代码下另测 60 条：**51.7% vs 66.7%（+15.0%）**。方向一致。

**判断早就做出来了，只是结果只用来决定"深读哪几篇"，而交给下游的排序仍按词法分数。**

## 改动

`_order_by_plan(plan, candidates)`：把阅读计划选中的文档按它的顺序前置，未被选中的保持 BM25 原序跟在后面。

**它重排，不过滤**——未被点名的文档一个都不会丢。这与本模块所有其他排序偏好的规则一致。

## 效果（40 条端到端）

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 报错 | 0 | 0 |
| 拒答 | 0/40 | 0/40 |
| 延迟中位 | 10.0s | **9.8s** |
| `citation_integrity` | 0.9792 | **0.9875** |

## 为什么这不是"指标化妆"

一个必须区分的问题：把候选顺序改了，`hit@1` 会变好看，但如果读的还是同一批文档，
答案质量不会变——那就是指标化妆。

这次不是：
- `_order_by_plan` 的结果被**下游实际使用**（`_read_documents` 按新顺序读取，名额有限时优先读前面的）
- `citation_integrity` 0.9792 → **0.9875** 是**确定性指标**，不依赖任何 LLM 裁判
- 延迟还降了 0.2s（阅读计划的首选文档更短或更相关，深读更快）

## 边界

- 这是 **agentic 排序**，不是新增模型调用：用的是已有的 `_plan_reads`，零额外成本
- 不引入 embedding / rerank 模型 / 语义词表——判断来自 LLM 的自然语言推理，与 CLAUDE.md 的定位一致
- 剩余空间：`hit@4 = 0.7741` 意味着 top-4 内重排的上限是 0.774，而计划首选已达 0.703（435 条样本），**接近天花板**。再往上要走 hit@4 → hit@12 那段（rank 5-12 的 33 条）
