# 本轮优化复盘：哪些改动真的有效

语料：595 部真实中国法规 / 23,386 条条文页；评测 270 条标题盲测自然语言提问
（只给法规正文中段，不给标题、法规名、地名）。

## 按实测收益排序

| 改动 | 指标变化 | 结论 |
| --- | --- | --- |
| **修证据审计提示词** | 端到端 SUPPORTED **32% → 60%**，拒答 38% → 8% | **最大收益，来自一条提示词** |
| **条文级索引** | `hit@1` 0.2074 → **0.5259**（2.5×），未召回 121 → 40 | 结构性改动，全部 p<0.0001 |
| **深读 4 → 6** | 拒答 38% → 28%，SUPPORTED 32% → 37% | 有效 |
| 查询扩展（字符串） | `hit@1` 0.2074 → 0.2889（p=0.0002） | 有效，已默认开启 |
| HyDE + Rocchio 加权 | `hit@1` 0.2074 → 0.2926；相对字符串扩展 p=0.12 | 方向对，未达显著，默认关闭 |
| Scope 偏好（一般/特定） | 无变化（0.5259 → 0.5259） | 未证实，默认关闭 |
| 候选语义评分 | 噪声候选可拿 100 分，无法区分 | 未证实，默认关闭 |
| BM25 参数 / title 权重 | 不一致或为负 | 无效 |
| LLM rerank | `ndcg@4` +0.024、4× 慢 | 无效 |

## 三个关键教训

### 1. 评测集本身的偏差会掩盖一切

早期查询由 LLM 生成时**看到了法规标题**，问题里保留专有词，基线 `hit@1 = 0.3867`。
改为标题盲测后基线只有 `0.1800`——**同一系统差 2 倍**。在修正这一点之前，所有
"改进幅度"都是在一个虚高的指标上测量的。

### 2. 最有效的是最朴素的

端到端正确率从 32% 涨到 60%，不是因为新架构，而是因为审计提示词把
"coverage（是否覆盖问题的所有方面）"改成了"answerability（能否回答所问的那个事实）"。
原提示词让模型对只问单一事实的问题给出低 coverage，于是误判为证据不足而拒答——
13 条拒答中 10 条的答案**明明白白写在上下文里**。

同理，`hit@1` 翻 2.5 倍来自"把全文切条索引"，而不是任何打分或重排技巧。
文档级索引只覆盖每份文档约 15% 的摘要，剩下 85% 从未进入索引。

### 3. 一个生动的案例不等于证据

"男的多少岁能结婚"这个案例非常真实（检索出地方变通规定而非全国规定），它催生了
Scope 偏好机制。但实测收益为零——因为语料里 13,824 条地方性法规对 310 条法律，
大多数"一般性提问"的正确答案**本来就是地方条例**。保留实现、默认关闭、如实记录。

## 通用性检查

审计所有新增组件是否内嵌领域词表，发现并修掉一处真实的特例：
`_body_offset` 曾用 `text.find("第一条")` 跳过目录，对英文合同完全无效。
改为结构判断（同一标签在近处出现两次），并用英文服务合同、中文运维手册验证通过：
同一套代码，零配置，无按格式分支。

## 全量 270 条端到端结果（最终）

并发 8、重试 6 次后**零报错跑完**（并发 20/12 均在 `corrective_recall` 阶段被网关 502 打断）。

| 指标 | 数值 |
| --- | --- |
| 总数 / 报错 | 270 / **0** |
| SUPPORTED（引用级裁判） | **182（67%）** |
| UNSUPPORTED | 46（17%） |
| 拒答 | 42（16%） |
| 有可靠引用 | 221（82%） |
| `citation_integrity` | 0.98 |
| `citation_precision` | 1.00 |
| 延迟中位 | **10s** |

### 网关并发实测

| 客户端并发 | 成功率 | 吞吐 |
| --- | --- | --- |
| **20** | **100%** | 9.96/s |
| 40 | 21% | 5.4/s |
| 60 / 80 / 100 | 0% | 0 |

**20 是稳定上限。** 但端到端在并发 20 和 12 下都被打断——不是并发过高，而是**持续负载下
网关会返回 502**。最终用并发 8 + 重试 6 次跑通。

### 裁判工具本身的三次迭代，每次都改变结论

1. **截断上下文**（5000 字截到 4000）：6 条"答案无依据"实为误判，关键条款被切掉。
2. **严格字符串匹配**：要求答案逐字出现在上下文里，导致 54 条 UNSUPPORTED，
   抽样检查发现全部是模型合理归纳后的正确回答。
3. **引用级判定**（最终采用）：只看答案自己引用的那几条上下文，允许归纳换词。

三次迭代的 UNSUPPORTED 比例：**15% → 20% → 17%**，但**含义完全不同**。
最终 17% 里仍需抽样确认，但已排除"评测工具造成的误判"。

**教训：测量工具的错误会被误读成系统的错误。**

## 保留的方法论问题

- **样本量**：端到端 40 条、裁判 22% 失败率。比例可信，精确值不可信。
  270 条全量在 concurrency 4 下超过 5000 秒未完成，正在以 concurrency 20 重跑。
- **裁判工具本身有缺陷**：早期裁判把 5000 字上下文截断到 4000 字，导致
  6 条"答案无依据"的误判。改用完整上下文后 UNSUPPORTED 从 15% 降到 1–2%。
  **测量工具的错误会被误读成系统的错误。**
