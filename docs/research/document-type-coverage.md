# 各类文档的检索覆盖：用真实文档检验

之前所有评测只覆盖两种文档（中文法规、美国法典）。用户真正会用的是
**制度、合同、手册、申报表、操作指引**。这份记录用真实 .docx 补上这一块。

## 语料

`data/raw/real/` 里用户提供的 4 份真实公文：

| 文档 | 类型 | 字数 | 特征 |
| --- | --- | --- | --- |
| 网络通〔2026〕99号通知 | 正式公文 | 2,475 | 一/（一）/1. 三级编号 |
| 在岗技术革新系统申报指引 | 操作指引 | 1,734 | **含 5 张截图** |
| 负面清单及典型案例分析 | 条目式清单 | 1,491 | （二）…（十一）条目 |
| 在岗技术革新奖励申报模板 | **表单单据** | 1,413 | 字段名 + 空白选项 |

## 摄入阶段发现两个会阻断生产的缺陷

**4 份文档中有 3 份导致整批摄入失败。**

### ① 条文拆分的输出超出 token 上限

24,000 字窗口要求模型输出几十到几百个标签，推理模型的思考占满预算后
`finish_reason=length`，该错误直接让整批失败。

修：窗口降到 8,000 字、输出预算提高，并且**对 length 这一种情况降级重试**（窗口减半）。
重试只针对 length——网关 502、连接中断仍然抛错，不会被误认为"文档太长"。

### ② 标签带排版标点时定位失败

模板原文写 "1. 应用范围\*（可多选）"，模型转写为 "1.应用范围\*（可多选）"。
定位器只放宽了空白，星号和空格差异导致本应匹配的锚点失败。

修：把标签拆成**内容片段**，片段之间放宽空白**和排版标点**（星号、冒号、括号、破折号）。
内容字符仍必须按序出现——词语真的不同仍然失败，这是该保留的行为。

修复后**4 份文档全部摄入成功**，135 chunks，条文索引 + doc2query + scope 提取全开。

## 检索与问答质量（14 条问题，覆盖 4 种类型）

| 文档类型 | 答案正确 |
| --- | --- |
| 通知（正式公文） | **5/6** |
| 操作指引（含截图） | 1/2（其中 1 条实为正确，判定过严） |
| 负面清单（条目式） | 3/4 |
| **申报模板（表单单据）** | **2/2** |
| **总计** | **11/14（79%）** |

**表单类文档 2/2**——这是最出乎意料的一项，说明按条文拆分对"字段名 + 选项"的结构同样有效。

## 两条拒答的追查：不是检索问题

未命中的 2 条（"淘汰比例不低于多少"、"已经获过奖还能再报吗"）逐个复查：

```
Q: 已经获得过奖励的成果还能再报吗？
   检索排名: #1 doc-69e53b76（负面清单，正确）   ← 检索完全正确
   单独查询: 回答正确「…不重复奖励 [C8]」
Q: 合规性评审淘汰比例不得低于多少？
   检索排名: #1 doc-32eaa4（通知，正确）        ← 检索完全正确
```

**两条都排在第 1 位，单独查询时答案正确。** 混合评测里的拒答是并发下的偶发不稳，
不是检索缺陷——但这本身是下一个要查的问题。

## 结论：检索本身是通用的

- 公文、条目清单、表单单据、含截图的指引——**四种结构完全不同的真实文档都能正确解析、索引和检索**
- 条文拆分不依赖"第X条"这类中文编号：表单的 "1. 成果载体\*" 同样被识别为单元
- 之前发现的所有语言/格式假设（查询扩展字符上限、拒答语言、标题权重、标签标点）
  都已修成与语言和文档类型无关的实现

## 保留的边界

- 14 条问题的样本很小，只能说明"各类型都能工作"，不能给出每类的精确准确率
- 并发下的偶发拒答未定位
- 每类文档各只有 1–2 份真实样本
